# Contributing to Ideavelo

Ideavelo builds proprietary AI-enabled platforms and software products. Contributions to private repositories require explicit access and authorization.

## Recommended workflow

1. Identify the issue, requirement or approved task.
2. Read the target repository's README, architecture notes and operational constraints.
3. Reconcile current branches, open pull requests, active deployments and concurrent work.
4. Create a focused branch from the appropriate base.
5. Implement and validate the change with relevant tests.
6. Open a pull request using the repository template, including evidence, risks and rollback.
7. Obtain the reviews and required checks specified by the project before merging.

## Review expectations

- Correctness, maintainability and documented design trade-offs.
- Authorization, secrets management, privacy and dependency security.
- Data integrity, API compatibility, concurrency and failure recovery.
- AI-agent permissions, inference budgets, auditability and human oversight when relevant.
- Reproducible test results and accurate operational evidence.

See [Engineering Standards](docs/ENGINEERING.md).

## Responsible collaboration

Communicate respectfully, ground decisions in technical evidence and preserve existing work. Never disclose private code, customer information or sensitive deployment details in public issues.

## Security issues

Follow [SECURITY.md](SECURITY.md). Do not disclose exploitable vulnerabilities publicly.

## Licensing

Do not assume any project is open source. Each repository defines its own licensing and access conditions.
