# Security Policy

Ideavelo welcomes responsible vulnerability reports concerning its software and public-facing services.

## Private disclosure

**Do not open public issues** containing exploit details, credentials, customer data or sensitive infrastructure information.

Where enabled, use GitHub's **Private vulnerability reporting** feature for the affected repository. Otherwise, use the official contact channel listed at https://ideavelo.tech to request a secure reporting method before transmitting sensitive technical details.

## What to include

- A concise description of the suspected issue and its impact.
- The affected component and relevant version, if known.
- Safe reproduction steps without secrets or private data.
- A secure way to coordinate follow-up.

## Research boundaries

- Do not access, alter, extract or disclose data without authorization.
- Do not conduct disruptive tests, social engineering or production exploitation.
- Do not publish technical exploit details before coordinated remediation.

## Response expectations

Response times, support commitments and any reward programs are not established by this public document. Project-specific security policies take precedence.
